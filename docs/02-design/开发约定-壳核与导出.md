## 1. 壳 / 核边界与模块职责

### 1.1 调用方向（硬规则）

```
shell-app / slot-dnd / property-panel
        │  只向下调用
        ▼
  template-store（唯一可变实例真相源）
        │  派发快照 / 命令
        ▼
  render-core（VTable）← 只读渲染；禁止反向依赖壳 UI
        │
        ├─► export-html（可读 store + 可选读核 DOM/option）
        └─► export-png（截取核预览区域）
```

| 规则 | 说明 |
|------|------|
| 单向依赖 | **壳 → store → 核**；核**不得** import 壳组件、DnD 状态机、路由 |
| 状态归属 | **template-store** 持有当前 `TemplateInstance`；核仅持有 VTable 实例句柄与最近一次 option 缓存 |
| DnD 归属 | **slot-dnd 在壳**；hit-test、幽灵回弹、占用判定均在壳；落成后只调 `addBlock` / `removeBlock` |
| 禁止 | 核内做通用画布 DnD；把 VTable 插件当低代码运行时；模板逻辑写死在不可复用单页脚本（FR-07） |

### 1.2 模块职责（可实现粒度）

| 模块 | 持有 | 输入 | 输出 | 禁止 |
|------|------|------|------|------|
| **shell-app** | 路由、P1/P2/P3 布局、离开确认（FR-10） | 用户导航 | 挂载核、打开导出 | 直接改 VTable option |
| **template-store** | `TemplateInstance`、脏标记、一步撤销栈（FR-11） | load/set/add/remove/theme | 校验结果、快照、error code | UI 文案、DOM |
| **slot-dnd** | 拖拽手势态、命中 slotId | 指针事件 + 模板 `blockSlots` | 成功则 `addBlock`；失败 toast | 未命中时写 JSON；核内 hit-test |
| **property-panel** | 当前选中 `slotId` / `blockId` | 用户编辑 | `setSlot` / 强调 token / `removeBlock` | 增删行列入口 |
| **render-core** | VTable 实例 | `TemplateInstance` 快照 | 预览；`getPreviewEl()` 供 PNG | DnD；模板市场；剪贴板权限 UX |
| **export-html** | 无长期状态 | 实例快照 | HTML 字符串或错误码 | 依赖未提供的私有 CSS/字体 URL |
| **export-png** | 无长期状态 | 预览根节点 | PNG Blob 或错误码 | 在渲染中/错误态强行出图（壳应先禁用） |
| **embed-api** | — | — | 文档化 `mount` 预留 | 本期交付 npm/SDK |

### 1.3 与 UX 拖入反馈的对齐（只约定数据侧）

对齐 `编辑台操作体验深化.md` §3（不改 UX 文件）：

| UX 表现 | 开发侧约定 |
|---------|------------|
| 可放槽高亮 | 壳根据模板 `layout.blockSlots[].accept` 做类型过滤后高亮 |
| 未命中回弹 +「请放到表内虚线槽位」 | 壳不调用 store；错误码 `SLOT_MISS`（可不上抛，仅壳内） |
| 类型不匹配「这里不能放这个区块」 | `BLOCK_TYPE_REJECT`；不写 JSON |
| 同槽再拖入 | **已对齐 replace**：默认 `blockSlotPolicy: "replace"`（对齐需求 §8 + 交互 G-UX-05）；仍可保留 `"reject"` 开关备查，本期不用 |
| 删除区块二次确认 | 壳 UX；确认后 `removeBlock`；JSON 无残留（FR-09） |
| 空槽占位不进导出 | 导出时 `value === undefined \| null \| ""` → 输出空字符串；**不**输出占位句（对齐 UX-T2 假设） |

### 1.4 本期富编辑范围（Fill · 用户已锁）

> 状态：**用户 2026-10-20 已锁 Fill** · **Mid / Heavy 本期不做** · **不开码**（本文只定边界）  
> 路径：壳 JSON（`template-store`）→ 适配层 → VTable `option`；**不换核、不开自由画布**。

#### 本期纳入（Fill）

| 能力 | 分层落点 | 说明 |
|------|----------|------|
| **有限合并手感加深** | 壳 UX + `layout.merges` ⊆ `allowedMerges` → 适配 → `customMergeCell` | 选区 / 预览闪边 / 一键还原等壳体验；**仍限允许区**；禁 Excel 拖角合并（OUT-9） |

| **对齐** | 槽/格实例态（如 `align`）→ option / 导出 | 左中右；另存可写入实例；默认建议数字右 / 文案左 |

#### 本期明确不做

| 档 / 项 | 说明 |
|---------|------|
| **Mid 结构项** | 列宽拖（若未列入 Fill）、**有限增行**（封顶增行）等 → **本期不做**；若未来要做须另议并可能重开 OUT |

## 2. 模板数据契约 <!-- G-AR-01 -->

> 语义锁定；字段名实现期可微调，但须保持下表「必填/可选」与类型。完整运行时对象 = **底稿 TemplateDefinition** + **用户实例覆盖**。

### 2.1 顶层 `TemplateInstance`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `schemaVersion` | `string` | 建议 | 如 `"1.0"`；损坏/过旧时便于拒绝 |
| `templateId` | `string` | **是** | 底稿 ID（如 `insurance-compare-v1`）；对齐 U-1 的 T1/T2/T3 逻辑名 |
| `themeId` | `string` | **是** | 主题 id；缺失 → 回退默认（见 §4） |
| `themeTokens` | `ThemeTokens` | 否 | 覆盖 token；有则优先于主题包 |
| `slots` | `Record<string, SlotValue>` | **是** | 文案/数值槽；键 = 逻辑槽 ID |
| `blocks` | `BlockDesc[]` | **是** | 可空数组；已落入表内区块 |
| `layout` | `LayoutSpec` | **是** | 结构约束（钉列、合并、区块槽定义） |
| `meta` | `object` | 否 | 显示名、用途一句等；不影响渲染 |

### 2.2 `ThemeTokens`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `primary` | `string` (CSS color) | **是**（若对象存在） | 表头/分区主色 |
| `zebra` | `boolean \| string` | 否 | `true`/`false` 或斑马纹色 |
| `emphasis` | `string` | 否 | 强调红字/底色 |
| `border` | `string` | 否 | 边框色 |
| `background` | `string` | 否 | 表底 |
| `tag` | `string` | 否 | 左栏标签色 |

#### 首发主题常量（pack-A3 已锁 · **不改 ADR**）

| `themeId` | 名称 | 是否默认 | 说明 |
|-----------|------|----------|------|
| `T-A` | 蓝白台账 | **是** | 缺失/未知 themeId 回退至此 |
| `T-B` | 墨青簿册 | 否 | |
| `T-C` | 暖灰金 | 否 | |

- 本期仅此 3 个 id；**无**用户自定义 hex 色盘。
- 各包具体 token 色值以 [U-2 色板草案](../03-ux/U-2-主题色板-草案.md) 为准；契约层只认上表 id。
- 本锁仅充实 `ThemeTokens` / `themeId` 枚举，**不推翻** [ADR-001](../07-decisions/ADR-001-主核与壳核分层.md)。

### 2.3 `slots` 与槽值

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 键 | `string` | — | 逻辑 ID，建议与 U-1 草案一致：`obj.name.a`、`row.3.val.b`、`plan.name`… |
| 值 `.text` / 裸值 | `string \| number` | 槽若存在则建议有值 | 实现可采 `string \| number` 或 `{ text, align?, emphasize? }` |
| `emphasize` | `"bold" \| "red" \| "bg" \| Array<…>` | 否 | 单元格强调；无则跟随主题默认 |

**空槽**：store 可保留键而值为 `""`；预览显示 UX 占位；**导出不含占位句**（ARCH 对齐 UX-T2 假设）。

### 2.4 `blocks[]` · `BlockDesc`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | **是** | 实例内唯一 |
| `type` | `"sectionBar" \| "groupHeader" \| "emphFooter" \| "leftTag"` | **是** | 对齐版式清单 §5.2 四类 |
| `slotId` | `string` | **是** | 必须 ∈ `layout.blockSlots[].id` |
| `props.label` / `props.text` | `string` | 视类型 | 色条可用 `label`；标题/注脚/标签用 `text` |
| `props` 其他 | `object` | 否 | 实现期扩展；未知键忽略并告警 |

### 2.5 `layout` · `LayoutSpec`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `rowCount` | `number` | 建议 | 锁死行数；禁止运行时增删行 |
| `colCount` | `number` | 建议 | 含左栏；T1 首发假设数据列 3（U-1-b） |
| `frozenColCount` | `number` | 否 | 钉列；宽表用；默认 0 |
| `merges` | `MergeRange[]` | 否 | 当前生效合并 |
| `allowedMerges` | `MergeRange[]` | 否 | **有限合并**可调范围；非此集合无合并入口（需求 §8） |
| `structuralMerges` | `MergeRange[]` | 否 | **锁死**不可拆（如左栏整列） |
| `blockSlots` | `BlockSlotDef[]` | **是**（若启用 FR-08） | 可拖入锚点定义 |
| `headerLevels` | `number` | 否 | 多级表头层数 1～3 |

`MergeRange`：`{ start: [row, col], end: [row, col] }`（0-based；闭区间）。

`BlockSlotDef`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | **是** | 如 `row-gap-3`、`footer-1`、`left-r5` |
| `accept` | `BlockType[]` | **是** | 允许的 `type` 列表；类型不匹配 → `BLOCK_TYPE_REJECT` |
| `rowHint` / `region` | `string` | 否 | 辅助壳高亮；如 `between-rows` / `footer` / `left-tag` |
| `occupiedPolicy` | `"replace" \| "reject"` | 否 | 缺省跟全局 `blockSlotPolicy`；**默认 replace（ARCH-T1 已对齐）** |

**互斥（对齐 U-1-c 假设）**：若两 `BlockSlotDef` 标注同一 `region` 且 `mutexGroup` 相同，则同组仅允许一个 block；后写入按 policy 替换或拒绝。

### 2.6 最小合法示例（概念）

```json

  "themeId": "T-A",

      "id": "b1",

  ],

    "rowCount": 10,
    "colCount": 4,

    "structuralMerges": [],

      {
        "id": "row-gap-3",

  }

```

### 2.7 校验规则（load 时）

| 检查 | 失败码 |
|------|--------|
| JSON 解析失败 / 非对象 | `TEMPLATE_INVALID` |
| 缺 `templateId` / `slots` / `blocks` / `layout` | `TEMPLATE_INVALID` |
| `blocks[].slotId` ∉ `blockSlots` | `SLOT_UNKNOWN`（可降级：丢弃该 block + warn） |
| `blocks[].type` ∉ 对应 `accept` | `BLOCK_TYPE_REJECT`（丢弃或整表拒绝：**待确认 ARCH-T2**，假设 load 时丢弃并 warn） |
| `themeId` 未知且无 tokens | 不失败；`THEME_MISSING` + 默认主题 |

## 3. 对外接口骨架 <!-- G-AR-04 -->

### 3.1 类型与 CoreHandle

```ts
type BlockType = "sectionBar" | "groupHeader" | "emphFooter" | "leftTag"
type SlotValue = string | number | { text: string | number; emphasize?: string | string[] }

interface ThemeTokens {
  primary: string
  zebra?: boolean | string
  emphasis?: string
  border?: string
  background?: string
  tag?: string
}

interface BlockDesc {
  id: string
  type: BlockType
  slotId: string
  props?: { label?: string; text?: string; [k: string]: unknown }
}

interface TemplateJSON { /* 见 §2 TemplateInstance */ }

interface CoreOptions {
  /** 初始实例；可空则 mount 后 loadTemplate */
  initial?: TemplateJSON
  /** 同槽策略；默认 replace（ARCH-T1 已对齐） */
  blockSlotPolicy?: "replace" | "reject" // 默认 "replace"
  onError?: (err: CoreError) => void
}

interface CoreError {
  code: ErrorCode
  message: string
  details?: unknown
}

interface CoreHandle {
  loadTemplate(json: TemplateJSON): void
  applyTheme(themeId: string | ThemeTokens): void
  setSlot(slotId: string, value: SlotValue): void
  addBlock(block: BlockDesc): void
  removeBlock(blockId: string): void
  /** 有限合并：仅当 range ⊆ allowedMerges */
  setMerge?(range: { start: [number, number]; end: [number, number] }): void
  exportHtml(): Promise<string>
  exportPng(): Promise<Blob>
  /** PNG 用：预览根节点 */
  getPreviewEl(): HTMLElement | null
  destroy(): void
}

declare function mount(el: HTMLElement, options?: CoreOptions): CoreHandle
```

### 3.2 CoreHandle ↔ 壳事件对照

| 壳侧用户动作 | 壳模块 | 调用 | 核行为 |
|--------------|--------|------|--------|
| P1「使用此模板」 | shell-app | `loadTemplate(def)` | 重建 option 并渲染 |
| 改槽位失焦 | property-panel | `setSlot(id, v)` | 增量刷新单元格 |
| 切换主题 / 斑马纹 | property-panel | `applyTheme(...)` | 映射 VTable theme；允许 ≤300ms 淡入（UX） |
| 拖入命中并松手 | slot-dnd | `addBlock(...)` | 按 JSON 重算行/自定义单元格 |
| 移除区块 | property-panel | `removeBlock(id)` | 同步预览 |
| 复制 HTML | export 入口 | `exportHtml()` | 不改实例 |
| 下载 PNG | export 入口 | `exportPng()` ← 内用 `getPreviewEl()` | 截预览区 |
| 离开 P2 | shell-app | 读 store 脏标记；确认后可 `destroy` | — |
| 撤销一步 | shell-app | store.popUndo → `loadTemplate` 或细粒度回放 | 回到快照 |

嵌入宿主（二期）：只使用 `mount` + `CoreHandle`；**不必**挂载 slot-dnd。

> U-4 **已关=embed-A**（仅概念预留·不升规格）：`applyTheme` 的 `themeId` 仅认 `T-A`/`T-B`/`T-C`（缺省/未知 → `T-A`）；形态选项见 research U-4 对比，**本期仍不交付 SDK**。

## 4. 失败与错误码 <!-- G-AR-03 -->

### 4.1 错误码表

| code | 场景 | 壳呈现原则（文案权威在 UX） | 是否可重试 |
|------|------|-----------------------------|------------|
| `TEMPLATE_INVALID` | JSON 损坏 / 缺必填 | 预览错误态「表格渲染失败」+ 重试/回库；侧栏保留 | 是（重选模板） |
| `THEME_MISSING` | themeId 无包 | toast「主题不存在，已用默认」；回退 T-A | 否（已降级） |
| `SLOT_UNKNOWN` | setSlot / addBlock 未知 id | 拒绝写入；短提示 | 否 |
| `SLOT_MISS` | DnD 未命中 | 「请放到表内虚线槽位」；回弹 | 是（再拖） |
| `BLOCK_TYPE_REJECT` | accept 不匹配 | 「这里不能放这个区块」 | 是 |
| `BLOCK_SLOT_OCCUPIED` | policy=reject 且已占用 | 「该位置已有区块，请先删除或换空槽」 | 是 |
| `BLOCK_NOT_FOUND` | removeBlock 无此 id | 静默或开发 warn；UI 可刷新选中 | — |
| `MERGE_NOT_ALLOWED` | 超出 allowedMerges / 拆 structural | 「此处不能合并…」（需求禁操作文案） | 否 |
| `RENDER_FAIL` | VTable 抛错 / 挂载失败 | 中区错误 +「重试」；**保留 JSON** | 是 |
| `EXPORT_HTML_FAIL` | 序列化/剪贴板失败 | 「复制失败，请重试」；防连点结束 | 是 |
| `EXPORT_PNG_FAIL` | 截图失败 | 「导出失败，请重试」；按钮恢复 | 是 |
| `EXPORT_BLOCKED_RENDERING` | 预览仍 loading/error | 禁用导出；「请等待表格渲染完成」 | 待就绪 |
| `TEMPLATE_LIST_FAIL` | 读「我的模板」（IndexedDB）失败；系统模板内置随包，不受影响 | 「我的」分区错误态 +「重试」；系统模板照常可选 | 是 |
| `TEMPLATE_SAVE_FAIL` | 另存写入 IndexedDB 失败；`details.reason`：`quota`（配额满或超 ARCH-T5 上限）/ `io`（其他） | `quota` →「我的模板已满，请先删除不用的」；`io` →「保存失败，请重试」（文案以交互另存说明为准）；弹窗保留已填名称；**不改**当前实例 | `io` 是；`quota` 删除后再试 |
| `DRAFT_RESTORE_FAIL` | 重开页面时读草稿失败（读不到库、JSON 损坏、校验不过、模板已不存在） | 按模板初始状态打开（模板不在则回模板库）+ 顶部一句提示；坏草稿删除 | 否（已降级） |
| `DRAFT_SAVE_FAIL` | 自动保存草稿写入失败（含配额满、隐私模式） | 顶部一次性轻提示「自动保存失败，刷新后可能无法恢复」，本次会话不再重复；**不打断编辑** | 是（下次改动自动再写） |
| `EXPORT_PNG_TOO_LARGE` | 增强期：倍率后输出像素超门槛（见 §5.2） | 「图片太大，请改用 2x」；不自动降倍 | 是（降倍率） |

### 4.2 可观测性约定

| 项 | 约定 |
|----|------|
| 上报形态 | 开发期 `console.warn/error` 带 `code`；本期**不做**远程日志 SDK |
| 用户可见 | 只白话；**禁止**把 `code` 直接甩给用户 |
| 降级 | 单 block 坏 → 可丢弃该 block 继续渲染（须 warn）；整模板坏 → 不半渲染糊弄 |
| 保留实例 | `RENDER_FAIL` / 导出失败**不得**清空 store |

## 5. 导出链路约定 <!-- G-AR-02 -->

### 5.1 HTML（`exportHtml`）

| 项 | 约定 |
|----|------|
| 产物 | **可粘贴片段**（表 + 必要样式），非完整站点 |
| 样式范围 | **内联**到单元格/`<table>`/`<tr>`/`<td>` 的 color/background/border/font-weight/text-align；或单段 `<style>` 仅含本表 class，class 名加前缀如 `pt-` |
| 禁止 | 依赖未随片段提供的外链 CSS/字体/图片；内联 `<script>`；事件处理器属性 |
| 安全 | 槽位与 block 文案一律**文本转义**（需求 §9）；防 XSS |
| 空槽 | 输出空字符串，**不**输出占位句（UX-T2 假设） |
| 合并 / 区块 | `rowspan`/`colspan` 与色条/分组行须体现在 DOM 结构；与预览同源数据 |
| 失败 | 抛/返回 `EXPORT_HTML_FAIL`；壳 toast + 可重试；过程防连点（FR-12） |

### 5.2 PNG（`exportPng`）

| 项 | 约定 |
|----|------|
| 截取区域 | **MVP 起即用离屏同源重绘**（2026-10-20 回应陌生人测试 Q-007）：用同一个 `toOption(store)` 在页面外新建临时 VTable 实例（`canvasWidth/canvasHeight:"auto"`，关动画）→ `exportImg()` → 销毁。导出**全表**：横滚看不到的列也进 PNG，钉列只出现一次；不截 `getPreviewEl()`。增强期沿用同一路径，只加倍率选项与透明底，详见 [增强期-设计增量.md](增强期-设计增量.md) §5.1。**本期不做**选区导出 |
| 尺寸 | **MVP 固定 2×，无倍率选项**。四周留白 **16 CSS px**。输出宽 = (表格内容宽 + 32) × 2，输出高 = (表格内容高 + 32) × 2，允许 ±2px。「表格内容宽/高」= 全部列宽之和 / 全部行高之和 **+ 表格外框线**（默认主题上下左右各 1px，宽高各 +2；CSS px，含钉列、含横滚隐藏部分），不含编辑台留白、16px 留白与滚动条；与设计增量 §5.1、FR-24 同一口径（D-1，PoC 实测 480+2=482 → 2× 输出 1028）。MVP 留白区填主题 `paper` token 色（不透明）。**增强期按 FR-24 支持 1/2/3×**，留白区透明，超像素门槛按 `EXPORT_PNG_TOO_LARGE` 拦截（门槛与测法见设计增量 §5.1）。ARCH-T3 |
| 一致 | 与预览一致；允许 1～2px 抗锯齿差（FR-06）。**比对方法**（黑盒可做）：① 用调试入口（§6.2）读「表格内容宽/高」，核对 PNG 像素尺寸符合上式；② 把 PNG 按 50% 缩放，与预览并排：行列数、每格文字、合并区、区块行、强调都一致；③ 预览横滚到最右，最右几列也出现在 PNG；④ 任取 3 个单元格取色，底色与当前主题 token 色值一致（抗锯齿边缘除外） |
| 过程 | 生成中禁用按钮；短进度文案「正在生成图片…」；**本期不可取消**（UX 假设） |
| 失败 | `EXPORT_PNG_FAIL`；可重试 |
| 就绪门禁 | 渲染中或 `RENDER_FAIL` → `EXPORT_BLOCKED_RENDERING`，壳禁用双按钮 |

### 5.3 导出前壳检查（体验，非核内）

| 检查 | 行为 |
|------|------|
| 预览 loading / error | 禁用 HTML/PNG |
| 大量空槽 | **不阻断**（UX-T4 假设）；不在契约层强制二次确认 |
| Excel | **无 API、无入口** |

## 6. 规模与性能约束 <!-- G-AR-05 -->

对齐需求 §9；作为开发**硬约束**（超出不承诺）。

| 约束 | 数值 / 规则 |
|------|-------------|
| 表规模 | ≤ **20 行 × 12 列**（含合并视觉格） |
| 钉列 | `frozenColCount` ≤ 2（首发假设 0 或 1） |
| blocks | 单实例建议 ≤ **20**；同 `mutexGroup` 至多 1 个（视 policy） |
| 主题切换 | 体感即时；允许整表淡入 ≤300ms；**勿**整页 loading |
| 单次 setSlot / addBlock | 预览更新体感 ≤200ms 级（UX 文档约定，非正式 SLA） |
| PNG | 允许数秒；须防连点 |
| 终端 | 桌面 Chromium / Safari 近两版优先；不做移动端完整编辑 |
| 持久化 | **用户另存模板**：与预制模板 JSON **同构**（`TemplateDefinition`）；本期存 **IndexedDB**（经 `TemplateRepo` 封装 idb-keyval，脚手架选型 Q7 已锁，键名见 §6.2）；**账号云同步后置**。编辑中草稿可同浏览器恢复（假设）。 |

### 6.1 用户模板另存与复用（用户已锁定方向 · 不开码）

| 项 | 约定 |
|----|------|
| 能力 | 编辑台可将**当前实例**另存为用户模板，进入模板库「我的」分区，下次选用即复用 |
| 数据 | 另存产物 = 完整 `TemplateDefinition`（与预制模板 **同 schema**）；可带 `origin: "user"`、`sourceTemplateId`、`savedAt` |
| 存储 | 本期：**本机 IndexedDB**（`TemplateRepo` → idb-keyval，Q7 已锁；键名见 §6.2）；仅 PNG 倍率等小偏好用 localStorage；**不做**账号云、不做多端同步 |
| 配额 | 假设用户模板 ≤ **50** 份或总 ≤ **2MB**（超限提示清理；数值 **ARCH-T5 待确认**） |
| 边界 | **不是**自由画布；不新增画布库；仍走 U-6=A 槽位 |
| 模块 | 壳 `template-store` + 模板库 UI；核只消费 JSON |


### 6.2 可测性与调试入口（回应陌生人测试 Q-014 / Q-015 · 2026-10-20）

只在**测试构建**里打开，正式发布构建里整段代码被去掉，用户看不到。

| 项 | 约定 |
|----|------|
| 测试构建 | `pnpm build --mode e2e`（读 `.env.e2e` 里的 `VITE_PT_DEBUG=1`）；`pnpm dev` 默认也打开。正式 `pnpm build` 时 `VITE_PT_DEBUG` 不设，相关代码经 `if (import.meta.env.VITE_PT_DEBUG)` 在打包时被摇树去掉 |
| 调试面板 | URL 加 `?pt-debug=1` → 页面右下角出现只读小面板：①「复制当前实例 JSON」②「复制已存模板 JSON（全部）」③ 显示「表格内容宽 × 高（CSS px，含外框）」与「PNG 预估像素」=（内容宽+32）×（内容高+32）×倍率²，含四周留白（D-3）④ 显示当前 `schemaVersion`、`themeId`。面板只读，不能改数据 |
| 故障注入 | URL 加 `?pt-fault=<码>[,<码>]` → 对应环节下一次调用直接按该失败码失败（只失败一次，重试即恢复，便于验「可重试」）；加 `!` 后缀如 `RENDER_FAIL!` 表示一直失败。支持的码：`DRAFT_RESTORE_FAIL`、`DRAFT_SAVE_FAIL`、`TEMPLATE_LIST_FAIL`、`RENDER_FAIL`、`EXPORT_HTML_FAIL`、`EXPORT_PNG_FAIL`、`TEMPLATE_SAVE_FAIL`、`PASTE_COMMIT_FAILED`、`EXPORT_PNG_TOO_LARGE`（增强期） |
| 门槛覆盖 | URL 加 `?pt-png-max=<像素数>` → 临时替换 PNG 像素门槛（增强期，用于验 `EXPORT_PNG_TOO_LARGE`，见设计增量 §5.1） |
| 注入点 | 每个模块入口一个 `faultGate(code)` 调用（壳 `src/shell/debug/fault.ts`）；核不读 URL，由壳在调用核前检查（守 G-1 核不引用壳） |
| 存储位置 | IndexedDB 库名 `pretty-table`，对象仓 `kv`（`createStore('pretty-table','kv')`）。DevTools → Application → IndexedDB 可直接查看 |
| 键名 | `tpl:<templateId>` → 用户另存的 `TemplateDefinition`（含 `origin:"user"`、`sourceTemplateId`、`savedAt`）；`draft:current` → 当前编辑实例草稿（P-1 已拍板启用，规则见 §6.3）。localStorage 只有 `pt.pref.pngScale`（增强期倍率偏好） |
| 字段对照 | 实例与模板字段以本文 §2（`TemplateInstance` / `slots` / `blocks` / `layout`）和设计增量 §3.1（1.1 新字段）为准；百分比槽存比例（`0.25` = 25%） |
| 验收归属 | 能用故障注入触发的失败态走黑盒验收；无法注入的（如浏览器配额真满）改单测验收（`TemplateRepo` 用 fake-indexeddb 模拟） |

### 6.3 刷新恢复（FR-10 · P-1 用户 2026-10-20 已拍板「自动恢复最近一次」）

| 项 | 约定 |
|----|------|
| 存哪 | IndexedDB 库 `pretty-table` / 仓 `kv`，键 `draft:current`，只存一份（最近一次） |
| 存什么 | `{ schemaVersion, templateId, instance, savedAt }`；`instance` 即 store 当前 `TemplateInstance`（§2.1）。**不存**撤销快照、选中、粘贴预览等临时状态 |
| 何时写 | store 每次成功 commit 后防抖 **800ms** 写一次；页面 `visibilitychange` 变 hidden 或 `pagehide` 时立即补写一次。`pastePending`（粘贴预览中）不写，确认或取消后再写 |
| 何时删 | 用户选「不恢复，重新选模板」并二次确认后；从模板库换新模板并确认替换后（随即写入新实例的草稿）；读出的草稿损坏时 |
| 何时读 | 应用启动时读一次：没有草稿 → 正常进模板库；有 → 经 `SchemaMigrator` 校验后直接进编辑台，壳给「已恢复上次的编辑」提示（文案以页面流 §3 P2 为准） |
| 读失败 | `DRAFT_RESTORE_FAIL`：删坏草稿 → `templateId` 能找到就按模板初始状态打开，找不到回模板库 → 顶部一句提示。不弹窗、不白屏 |
| 写失败 | `DRAFT_SAVE_FAIL`：只 warn + 一次性轻提示，不重试轰炸，下次 commit 再试；编辑不受影响 |
| 撤销 | 恢复后撤销栈为空（撤销按钮灰），撤销记录不跨刷新 |
| 模块 | 壳 `DraftRepo`（与 `TemplateRepo` 共用 idb-keyval 自定义 store）；核不感知草稿 |
| 测法 | `?pt-fault=DRAFT_RESTORE_FAIL` / `DRAFT_SAVE_FAIL` 注入；调试面板可看 `draft:current` 内容 |

## 7. 风险 / 待确认

| ID | 项 | 当前假设 | 备注 |
|----|-----|----------|------|
| **ARCH-T1** | 同槽策略 | **已关**：默认 replace（对齐需求/交互） | — |
| **ARCH-T2** | load 时非法 block | 丢弃该 block + warn，不整表失败 | 可改 |
| **ARCH-T3** | PNG 像素比上限 | MVP 最大 2×；最长边目标 ≥1200px。**增强期按 FR-24 支持 3×**（已确认 2026-10-20） | 实现前可测校准 |
| **ARCH-T4** | 空槽导出 | 空字符串 | 对齐 UX-T2；若 PM 改口再调 |
| U-1 | 首发模板 | **已锁 α**：C-compare + C-detail（多列对比+单主体明细） | 不绑保险题材 |
| U-2 | 主题套数 | **已锁 pack-A3**：三套 `themeId`=`T-A`（蓝白默认）/`T-B`（墨青）/`T-C`（暖灰金）；无自定义 hex | 对齐 UX U-2 草案 |
| U-4 | 嵌入事件细节 | **已关=embed-A**：仅分层 + CoreHandle **概念预留**；无 npm/SDK、无宿主事件；见 [research/U-4-嵌入API形态对比](../research/U-4-嵌入API形态对比-2026-10-20.md) | 不进本期验收 |
| UX-T5 | 区块首发 2 或 4 类 | schema 四类都在；启用集由配置开关 | 灰显不可拖属壳 |
| **ARCH-T5** | 用户模板配额 | 假设 ≤50 份或 ≤2MB | 实现前可调 |
| **U-7** | 自由画布 | **本期不做**（另存模板 ≠ 画布） | 见 research 评估文 |

**风险（知悉，不催开码）**

1. JSON ↔ VTable option 适配层是主复杂度；版式越多样例，自定义行/单元格越多。  
2. HTML 内联与 Canvas 预览「同源观感」只能近似，需验收条带「可读一致」而非像素级。  
3. 同槽默认 replace（ARCH-T1 已对齐）；DnD 验收按替换路径写，勿再双写 reject 为默认。  
4. 有限合并的 `allowedMerges` 与 UX 面板步骤未完全写死（G-UX-01）——契约已留字段，交互细则归 UX。

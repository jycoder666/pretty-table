## 0. 一句话结论（给主控 / 用户扫读）

在**不翻画布、不换主核**前提下，用「加厚编辑层」回应「内容可自定义」。产品三包：

| 包 | 对齐 | 一句话 |
|----|------|--------|
| **包 Fill（轻量·推荐对照交互）** | UX 包 Fill | 有限合并手感+拆分+对齐+强调+区块微调；**不重开 OUT** |
| **包 Mid（中量）** | Fill + 有限结构 | Fill + 列宽拖 / 可选「封顶增行」；部分项**须重开 OUT** |
| **包 Heavy（近电子表）** | 对照放弃 | 筛选排序冻结填充柄等 → **易变弱 Excel**，本期建议明确不做 |

**结论（已锁）**：本期富编辑范围 = **Fill**。Mid（列宽拖/有限增行）与 Heavy（筛选/冻结/填充柄等）**本期不做**。开码仍待用户另行授权；需求已回写 Fill 定稿口径。

### 1.1 已锁「轻编辑」已覆盖（保留）

| 能力 | 出处 | 说明 |

| **有限合并**（模板允许区） | FR-03、§8「有限合并」、OUT-9 反面 | **能力在文档，手感偏薄** → 用户仍觉得「只能换肤」 |
| 表内区块拖入 4 类 | FR-08、U-6A | 结构扩展，非画布 |

### 1.2 相对用户原话的缺口

| 用户诉求 | 现状 | 缺口定性 |
|----------|------|----------|
| 交互更饱满 | 选→填槽→换肤→拖区块为主；合并「有入口口径但无选区/拆分/微反馈细则」 | **体验加厚**（多属改造，非换产品形态） |
| 表格内容自定义 | 以槽位为主；非槽结构格偏只读 | **编辑对象从「槽」扩到「允许区内的格」**（仍非任意格 Excel） |
| 例：合并单元格 | 仅允许区微调；禁 Excel 拖角合并（OUT-9）；禁操作文案已有 | **合并手感 + 拆分** 为高优先级候选（Fill 已列 TH-R1/R2） |
| 挖掘可集成能力 | 见 §2～§3 | 清单化后按处置表收口，避免一次做满 |

### 1.3 与成功标准 / 反例的张力（须明示）

需求 §1 成功标准第 3 条：「不出现公式栏/随意增删行列等『弱 Excel』能力入口」；§5.1 反例含增删行列。  
→ **包 Fill** 可在不改该标准下加厚；**包 Mid 的增行**、**包 Heavy** 会直接顶撞该条，须用户知情后才可改需求。

## 4. 三套范围包（与 UX「包 Fill」对齐）

### 4.0 与交互草案的映射

| UX 包（`编辑能力-加厚草案.md` §4） | 本文件产品包 | 关系 |
|----------------------------------|--------------|------|
| **包 Fill（交互建议默认）** | **包 Fill（轻量）** | **同口径**：S1/S2+R1/R2+C1/C2/C3+B1/B2+F1/F2/F3 |
| 包 Slim | （可作 Fill 的缩水备选，不单列拍板） | 仅合并手感+文案强调+区块；更小 |
| 包 Stretch | **包 Mid 子集** | Fill + 列宽 R3 |
| （交互未单列增行） | **包 Mid 扩展** | 可选 TH-R4 有限增行 → 须重开 OUT |
| 不做 R5/X1 等 | **包 Heavy = 对照放弃** | 近电子表能力全集 |

### 4.1 包 Fill · 轻量加厚（**已锁 · 本期范围**）

| 维 | 内容 |
|----|------|
| **改什么** | ① 多选相邻格→允许区合并（手感饱满）② 拆分（非 locked）③ 对齐三钮 ④ 强调入口可见 ⑤ 区块样式 2～3 档 ⑥ 撤销覆盖合并/对齐 ⑦ 微反馈 |
| **为什么** | 直接回应「合并+内容自定义」；**不重开 OUT-1/9**；不碰画布；与 persona-A 自用作者匹配 |
| **验收草案** | 在允许区完成「选区→合并→改字→拆分→对齐→强调→另存→HTML/PNG」；非允许区仅禁操作提示；无增删行列入口；无画布入口 |
| **工期粗估** | **M**（壳交互+JSON 合并模型+导出一致性；核侧多靠 customMergeCell） |
| **边界** | 画布不做；embed 仅概念；主题仍三套无 hex |
| **放弃** | 任意合并、增删行列、筛选排序、列宽（留给 Mid） |

### 4.2 包 Mid · 中量（对照 · 非默认）

| 维 | 内容 |
|----|------|
| **改什么** | Fill **全部** + **列宽拖（吸附档）**；可选 **模板标 rowExtendable 的封顶增行（如 +3）** |
| **为什么** | 「表可变胖一点」；课表/价目类模板更灵活 |
| **验收草案** | Fill 全过；列宽拖后预览=导出；若开增行：仅标记区可加且达上限禁用并提示 |
| **工期粗估** | **M～L**（增行要改模板契约、OUT 回写、更多回归） |
| **边界** | 仍不做画布/公式/协作；增行**必须**先改需求 OUT-1 文案 |
| **放弃理由（相对 Heavy）** | 不做筛选排序冻结填充柄，避免弱 Excel |
| **风险** | 与成功标准「无随意增删行列入口」冲突——即便「有限」，用户心智易滑向 Excel |

### 4.3 包 Heavy · 近电子表（**建议明确不做本期**）

| 维 | 内容 |
|----|------|
| **改什么** | Mid + 排序/筛选/交互冻结/填充柄/粘贴扩表/（乃至公式） |
| **为什么（竞品有）** | TablesGenerator/文档表/VTable 插件均能支撑 |
| **放弃理由** | ① 顶撞 OUT-1/2/4/9 与成功标准#3 ② 与 ADR「非 Excel」叙事相反，易逼换主核心智 ③ persona-A 要的是精美展示表而非网格分析 ④ 工期 **L**，验收与导出一致性爆炸 |
| **边界** | 若未来要做，应**另立项**并重开 ADR/OUT，而非「pretty-table MVP 加厚」 |

## 2. PoC-1 VTable exportImg 3x + 像素上限

- **结论：通。**
- 实现：`src/poc/exportPng.ts`。按设计增量 §5.1：离屏容器（`position:fixed;left:-99999px`）新建 `ListTable`，`canvasWidth/Height:"auto"`、`animationAppear:false`、`pixelRatio:1` → `setPixelRatio(scale)` → 等画布定稿 → `exportImg()`（返回 `data:image/png` base64）→ 销毁实例。字体用系统字体栈常量，导出前 `await document.fonts.ready`。
- 像素门槛：**沿用文档值 16,777,216**（宽×高）。`measure(spec, scale)` 先用 1x 离屏实例取 CSS 尺寸、只算不画；超限直接抛 `ExportError('EXPORT_PNG_TOO_LARGE')`，**不创建倍率实例、不出产物、不自动降倍**；壳侧 toast 显示码 + 「改用 2x 或更低倍率重试」。
- 断言与实测：
  - 内容 CSS 482×362（4 列 160+120+100+100=480 + 外框 2px）；1x=482×362，2x=964×724，3x=1446×1086，均与 CSS×倍率误差 0px（要求 ±2px）。
  - 真重绘而非拉伸：独立颜色数 1x=41、3x=408（拉伸不会新增抗锯齿灰阶）；人工看 3x 图文字锐利。
  - 超限分支：大表 20 列×240px×30 行，3x 估算 14406×3726=53,676,756 > 16,777,216 → 抛 `EXPORT_PNG_TOO_LARGE`，离屏画布无残留（leaked=0），UI 按钮路径 toast 含 `EXPORT_PNG_TOO_LARGE` 与「2x」；同一大表 1x 未超限。
- 产物：`artifacts\poc1-vtable-1x.png`、`poc1-vtable-2x.png`、`poc1-vtable-3x.png`
- 兜底：未启用。
- 注意：
  1. 尺寸口径：auto 模式画布 = 列宽和 + 外框线（本例 +2px）。FR-24「2x 宽 = 预览宽×2（±2px）」按「含外框的内容 CSS 宽」计，误差 0。若 PM 口径是「列宽和」，2x 会多 4px，超 ±2px，需在开码时定口径（或主题去外框）。
  2. 门槛值 16,777,216 仍是文档保守值，**本 PoC 未做浏览器画布上限实测**（Chrome 实际更大）；Safari 未测。

## 3. PoC-2 透明底 PNG

- **结论：通。**
- 做法：主题 `underlayBackgroundColor: 'transparent'`，单元格 `bgColor` 保留（表头 #EEF2F7、表体 #FFFFFF）。
- 用例设计：auto 尺寸下画布 = 表格本身，**没有「表格以外」区域**；为了真正测到外围，另用固定画布（内容宽/高各 +40px）制造外围，再读像素：
  - 透明组（2x，1044×804）：右侧外围条带 59,496 像素 **非零 alpha=0**；右下角 alpha=0；格内 alpha=255。
  - 对照组（同尺寸，underlay=#ffffff）：右下角 alpha=255（证明透明是 underlay 生效，不是空画布）。
  - auto 透明组：四角 alpha=255（外框线/格底色占满，符合「格内纸色保留」）。
- 产物：`artifacts\poc2-transparent-2x.png`、`poc2-opaque-control-2x.png`、`poc2-transparent-auto-2x.png`
- 兜底：未启用。
- 注意：若外框有圆角（主题 `frameStyle.cornerRadius`），auto 模式四角会出现半透明像素，属预期；本 PoC 用 DEFAULT 主题外框。

## 4. PoC-3 @dnd-kit 键盘拖拽（Vue）

- **结论：通。** 选用官方 `@dnd-kit/vue` 0.5.1（底层 `@dnd-kit/dom` 0.5.1，内置 KeyboardSensor），无需替代方案。
- 3a 排序（`@dnd-kit/vue/sortable` 的 `useSortable` + `DragDropProvider @drag-end`）：聚焦第 1 项 → `Space` 拿起 → `ArrowDown`×2 → `Space` 放下；`onDragEnd` 读 `source.initialIndex → source.index`，调 Pinia `store.move()`。断言 store 与 DOM 顺序都从 `A,B,C,D` 变为 `B,C,A,D`。
- 3b 放入槽位（本项目真实场景，设计增量 §6.5 / F3 / P-8 前半）：`useDraggable` 区块 + `useDroppable` 槽位；`Space` 拿起 → `ArrowRight`×30 → `Space` 放下；drop 只发意图，由 `store.addBlock(slotId, blockType)` 写入（断言 `slot-1:title`），点「撤销」后恢复为空——证明走 store、一步可撤销。
- 产物：`artifacts\poc3-dnd-sorted.png`、`poc3-dnd-slot-filled.png`、`poc3-dnd-slot-undone.png`
- 兜底：未启用（自写指针 + 键盘路径不需要）。
- 注意：
  1. 0.x 版本，已 `--save-exact` 锁 0.5.1；升级前需重跑本用例。
  2. 键盘移动在非排序场景下是**按步长平移**（本例 30 次右移才到槽位），不是「方向键跳到下一个槽位」。真实槽位多、距离远时体验差，开码时应为槽位场景自定义键盘坐标/跳转（`KeyboardSensor` 选项或自补「Tab 选槽 + Enter 放下」），并配合需求要求的「点击添加」等价入口。
  3. 可拖元素需自加 `tabindex="0"` 才能聚焦。
  4. 未测：与 VTable 预览 Canvas 叠加层共存（P-8 后半）、读屏播报文案。

## 5. PoC-4 idb-keyval + TemplateRepo

- **结论：通。**
- 接口（文档只要求「外包一层 TemplateRepo」，签名未定，本 PoC 自定）：`src/poc/templateRepo.ts`
  ```ts
  interface TemplateRecord { id: string; name: string; schemaVersion: string; json: unknown; updatedAt?: number }
  interface TemplateRepo {
    save(t: TemplateRecord): Promise<TemplateRecord>   // 写入并打 updatedAt
    get(id: string): Promise<TemplateRecord | undefined>
    list(): Promise<TemplateRecord[]>                  // 按 updatedAt 升序
    remove(id: string): Promise<void>
  }
  createIdbTemplateRepo(dbName = 'pretty-table', storeName = 'templates')  // idb-keyval createStore 独立库
  ```
- 用例：清空 → save tpl-1、tpl-2 → remove tpl-2 → `page.reload()` → list=`["tpl-1"]`，get(tpl-1) 的 name/json 原样、updatedAt 为数字，get(tpl-2)=undefined。
- 兜底：不需要。
- 未测：容量上限、配额满/隐私模式下的报错、`file://` 下的行为。
